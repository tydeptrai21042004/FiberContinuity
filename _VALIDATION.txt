FiberContinuity v0.3.1 validation

What changed
------------
- Same-identity empty targets no longer become SAFE when payment/invoice or other recovery visibility is unavailable.
- Rollback checkpoint export is fail-closed: unexpected operational failures abort before mutation; only UnsupportedCapabilityError may continue without automatic rollback.
- Recovery exceptions during native restore, restart, or stabilization now attempt to restore the captured pre-mutation checkpoint.
- Full-visibility payment/invoice mismatches are hard FAIL/UNSAFE results; metadata-only mismatches remain warnings and unavailable visibility remains UNKNOWN.
- FiberJsAdapter requires real node/channel identifiers and channel state instead of synthesizing "unknown" / "channel-N" identifiers; duplicate channel IDs are rejected.
- Compatibility matching now parses semantic versions and no longer confuses rc10/rc11 with rc1.
- Archive validation now checks nested manifest shape, canonical base64, salt/IV lengths, record shapes, duplicate IDs, record-count bounds, and native-backup/browser size limits.
- Added regression tests for the new fail-closed behavior and FiberJsAdapter inspection rules.
- Added the repository files previously claimed by FILELIST/README: Node 24 pins, GitHub CI, .gitignore, .env.example, and evidence/runs/.gitkeep.
- Documentation/roadmap version language is aligned with v0.3.x as the current reviewer-ready reference implementation.
