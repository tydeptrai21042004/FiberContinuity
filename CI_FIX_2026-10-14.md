# GitHub Actions CI fix (14 October 2026)

## Errors addressed

1. **`No test suite found in file tests/hosted-api.test.mjs`:** This test file is written for Node's built-in `node:test` runner, not Vitest. The existing `vite.config.ts` now excludes **only this one file** from Vitest collection. All `.test.ts` Vitest suites remain discovered. The existing separate script `npm run test:hosted-api` continues to run all Node tests.
2. **`Some specified paths were not resolved, unable to cache dependencies`:** This ZIP does not contain `package-lock.json`. Both GitHub workflows now cache the existing npm download directory (`~/.npm`) with `actions/cache@v4` and a key based on `package.json`, without enabling `setup-node`'s lockfile-dependent `cache: npm` option. The workflows continue to install with `npm install --no-audit --no-fund`. Do not add `cache: npm` or `cache-dependency-path: package-lock.json` to `setup-node` until a real lockfile has been generated and committed.

## Validation after committing

```bash
npm install --no-audit --no-fund
npm run check
npm run test:hosted-api
npm run build
```

Expected: 15 Vitest test files, with the hosted API tests run by Node in the separate step. A `punycode` deprecation warning, if one appears, is not the reason for CI failing and is not addressed by this patch.

If your GitHub runner *still* prints the missing cache dependency-path error, inspect the workflow file in the **exact commit/ref** being run. The uploaded ZIP's original workflows did not contain a `setup-node` cache configuration, so the log may come from a different workflow revision than the ZIP.

No application logic, browser recovery logic, or assertions in the existing test files were modified.
